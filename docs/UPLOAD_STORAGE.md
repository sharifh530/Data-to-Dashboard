# Local raw upload storage

B05 storage slice, implemented 2026-09-17. Fixed isolated inspection was added on September 18; see [inspection](INSPECTION.md). Storage still accepts bytes without decoding CSV, opening SQLite, or executing source. Even malformed data is accepted as opaque bytes; a declared format is not proof of file validity.

After `npm run db:migrate` and local sign-in, POST the exact file bytes to `/api/v1/projects/{project_id}/raw-datasets?file_format=csv` (or `sqlite`). Supply the session cookie, exact Origin, X-CSRF-Token, Idempotency-Key, Content-Type `application/octet-stream`, and Content-Length. This storage-specific route is distinct from the future multipart inspection route. OpenAPI documents the binary body.

A 201 response returns ID, project ID, declared format, byte count, SHA-256, `status: awaiting_isolated_inspection` and `analysis_ready: false`. GET `/api/v1/datasets/{id}` retrieves that metadata; GET `/api/v1/datasets/{id}/raw` downloads the exact bytes as a nosniff octet-stream attachment with a server-generated filename. Both enforce ownership and tombstones. Downloads verify the checksum first. No preview, table selection, analysis run or inspection job is created.

Limits: 1 byte–10 MiB per file, 50 MiB total stored bytes per owner, two concurrent uploads per API process, 30 seconds to receive a body. Content-Length is required and independently checked against actual received bytes. Deleted/tombstoned rows continue counting until their raw storage is physically purged; a deletion/purge API is not implemented. Quota exhaustion returns 429. Missing length returns 411; size overflow 413; incorrect content type 415; timeout 408; length mismatch/disconnection 400. Authentication/ownership checks happen before receipt and again before storage. No database transaction is retained while waiting for the body.

Raw bytes, metadata, audit and idempotency record commit in one PostgreSQL transaction, avoiding filesystem/database orphan windows. The owner row serializes quota checks across API processes. Identical content and declared format under the same key replay for 24 hours; changed content returns 409. Application APIs never overwrite stored bytes. A database administrator can still modify them; this is not WORM storage. Integrity checks detect content corruption on download.

PostgreSQL bytea is a bounded local implementation (ADR-018), not the planned S3 production store. Bounded buffering creates memory copies; upload slots are per-process, and downloads currently buffer at most one file each without a global download cap. Hosted startup remains disabled. Production object storage, global rate limits and deletion/retention remain future milestones. The reviewed browser now supports uploads and separately requested inspections. Metadata adds `inspection_status`; the legacy `status` field remains `awaiting_isolated_inspection`, so use the new field to track inspection. `analysis_ready` remains false. Capability `raw_upload_storage_enabled` advertises storage; `uploads_enabled` remains false for the unfinished inspected-data-to-analysis workflow.
